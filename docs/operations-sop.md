# DomainHub 企业级操作流程与系统规范（Operations SOP）

> 文档状态：设计基线 / 待系统实施与验收  
> 适用范围：DomainHub 网站、管理后台、API、DNS/域名服务商集成、运维与客户支持  
> 目标：建立可审计、最小权限、可恢复、可追责的企业级操作制度。  
> 重要声明：本文定义目标控制和操作流程，不代表相关功能已在当前代码或生产环境实现。实施前必须完成技术设计、风险评审、测试和责任人签署。  
> 文档维护责任：平台负责人；安全负责人复核；财务、客服、运维负责人会签。  
> 复核频率：至少每季度一次；发生重大安全事件、监管要求变化或核心流程变更时立即复核。

## 0. 管理原则、术语与控制等级

### 0.1 不可妥协的原则

1. **最小权限：** 默认拒绝；按岗位、资源范围、动作和环境授权。临时权限必须有到期时间。
2. **职责分离：** 发起、审批、执行、复核不得由同一人包办高风险操作。超级管理员也不得绕过审计。
3. **强身份验证：** 所有后台管理人员必须启用 MFA；高风险操作再次验证身份。
4. **可追溯：** 所有关键操作记录操作者、时间、来源 IP、对象、变更前后摘要、结果和关联请求编号。
5. **安全失败：** 审计、权限、审批或风险服务不可用时，高风险写操作默认拒绝，不得静默放行。
6. **可恢复：** DNS、配额、账号权限、发布和数据变更必须有回滚或补偿步骤。
7. **证据保全：** 安全事件与滥用投诉相关证据应按法律、合同和隐私要求受控保存，不得擅自删除或修改。
8. **环境隔离：** 开发、测试、预发布、生产凭据和数据分离；禁止用生产密钥测试。

### 0.2 术语

- **RBAC：** 基于角色的访问控制；必要时叠加资源范围、属性和环境限制。
- **MFA：** 多因素认证。优先采用 FIDO2/WebAuthn 安全密钥或通行密钥；TOTP 可作为受控替代。短信不作为后台唯一第二因素。
- **双人复核：** 操作发起人与批准人不同；批准人审阅对象、影响、风险、回滚方案后批准。
- **高风险操作：** DNS 批量变更、域名删除/转移、配额大幅调整、管理员提权、审计配置变更、生产密钥轮换等。
- **P0/P1/P2：** 事件严重级别，见第 6 节。
- **RPO/RTO：** 可接受数据丢失时间 / 服务恢复时间目标，具体目标由业务负责人批准。

### 0.3 控制等级

| 等级 | 含义 | 示例 | 基本要求 |
|---|---|---|---|
| L1 | 一般只读 | 查看公开状态、本人资源 | 登录、基础限流 |
| L2 | 受控写入 | 修改本人资料、常规 DNS 单条记录 | MFA（后台）、审计、校验 |
| L3 | 高风险 | 批量 DNS、配额、域名转移、退款/资金相关动作 | 双人审批、二次验证、熔断、回滚 |
| L4 | 安全根控制 | 角色授权、MFA 策略、审计密钥/日志保留策略 | 双人审批、独立告警、外部留存 |

## 1. RBAC 与权限管理

### 1.1 角色定义与权限矩阵

所有权限必须绑定到具体主体（用户/服务账号）、角色、资源范围和有效期。以下为平台内置角色的最低权限基线，不允许通过前端隐藏按钮代替服务端授权。

| 能力 / 操作 | 超级管理员 | 运维 | 客服 | 财务 | 普通用户 |
|---|---:|---:|---:|---:|---:|
| 查看全局运行状态与告警 | 是 | 是 | 受限 | 受限 | 否 |
| 查看全局审计日志 | 是 | 安全相关只读 | 客服范围只读 | 财务范围只读 | 否 |
| 查看本人域名/订单/配额 | 是 | 排障所需 | 客服工单范围 | 财务订单范围 | 是（仅本人） |
| 修改本人资料与安全设置 | 代管需留痕 | 否 | 否 | 否 | 是 |
| 修改 DNS 记录 | 经审批 | 授权范围内 | 否 | 否 | 仅本人域名且受策略约束 |
| 批量 DNS 修改 | 双人审批 | 双人审批 | 否 | 否 | 否 |
| 域名注册/续费/赎回/转移 | 受控审批 | 执行或排障 | 申请/沟通 | 付款核验 | 发起本人申请 |
| 域名删除/放弃续费 | 双人审批 | 不得单独执行 | 否 | 费用核对 | 仅按产品规则申请 |
| 用户配额调整 | 双人审批 | 不得自行批准 | 提交申请 | 涉及计费时复核 | 否 |
| 退款/账务调整 | 否（不得单独记账） | 否 | 提交工单 | 双人审批执行 | 申请 |
| 用户冻结/解封 | 审批并留痕 | 安全事件授权执行 | 提交建议/紧急临时限制 | 否 | 否 |
| 创建/禁用子账号 | 是，双人复核 | 否 | 否 | 否 | 否 |
| 角色、权限策略变更 | 双人审批 | 否 | 否 | 否 | 否 |
| MFA 策略/审计策略变更 | 双人审批 | 安全负责人协作 | 否 | 否 | 否 |
| 发布、回滚与基础设施变更 | 审批 | 执行 | 否 | 否 | 否 |

**角色边界：**

- **超级管理员：** 管理平台配置、角色授权、子账号、紧急访问和全局策略。不得删除或改写审计记录；不得单人批准自己的高风险申请；不得默认拥有财务记账权。
- **运维：** 负责可用性、部署、监控、备份、DNS 服务集成和获批的故障处置。不得查看不必要的支付敏感数据，不得自行修改业务账务或提升自身权限。
- **客服：** 负责身份核验、工单、用户沟通、投诉受理和状态查询。默认无 DNS 写权限、无配额写权限、无资金操作权限；确需临时限制账号时走事件授权。
- **财务：** 负责对账、付款核验、退款和财务报表。不得管理系统角色、生产密钥或 DNS；财务写操作应双人复核并保留凭证。
- **普通用户：** 仅能访问本人资源、本人订单和本人授权的域名；只能执行产品明确开放且通过服务端校验的操作。

### 1.2 授权模型与执行规则

每次请求必须在服务端校验：

1. 主体是否有效、账号是否未冻结、会话是否未撤销。
2. 是否完成所需 MFA，MFA 状态是否仍有效。
3. 是否具有对应动作权限。
4. 资源是否属于该主体或其授权范围。
5. 授权是否过期、是否被撤销、是否受 IP/设备/环境条件限制。
6. 动作是否需要审批、额度检查、风险检查或二次确认。

授权结果采用**默认拒绝**。API 必须独立执行鉴权；不得依赖客户端传来的角色名称、用户 ID、资源所有权声明或隐藏按钮。对越权请求统一返回不泄露资源存在性的错误，并记录拒绝审计事件。

### 1.3 管理员后台强制 MFA

**政策：所有可访问管理后台、运维控制台、审计控制台的人员和高权限服务账号必须强制 MFA。**

- 首选 FIDO2/WebAuthn 安全密钥或通行密钥；允许 TOTP 作为备用方式。不得将邮箱验证码或短信作为唯一 MFA。
- 首次启用：管理员完成身份核验后绑定至少一个主因子和一个受控备用因子；恢复码只展示一次，要求离线保管。
- 登录策略：密码/主认证成功后必须完成 MFA；未注册 MFA 的管理员禁止进入后台，仅可进入 MFA 注册/恢复流程。
- 高风险操作：重新验证 MFA（step-up），验证有效窗口建议不超过 5 分钟；设备或地理位置异常时要求重新验证。
- 会话：后台会话空闲 15 分钟自动失效；最长连续会话 8 小时；敏感操作完成后可要求再次认证。刷新令牌轮换并可单点撤销。
- MFA 丢失：提交工单、双人身份核验、通知安全负责人；旧因子立即吊销，重新绑定后审计。不得由客服单人重置超级管理员 MFA。
- 紧急账户：仅保留最少数量，凭据离线封存；每次启用需双人批准、即时告警、限定时长（建议不超过 60 分钟）并事后复核。
- 服务账号：优先工作负载身份/短期凭据；不能交互登录；密钥定期轮换，权限仅限必要 API。

**验收标准：** 未完成 MFA 的管理员登录被服务端拒绝；直接调用管理 API 也被拒绝；MFA 解绑/恢复/紧急访问均产生完整审计记录；测试覆盖会话过期、因子撤销和重放攻击。

### 1.4 子账号与委派权限

支持由超级管理员创建受限子账号。子账号必须具备独立身份，不得共享主账号密码或 MFA 因子。

**创建流程：**

1. 申请人填写子账号用途、负责人、使用人、资源范围、权限动作、有效期和工单编号。
2. 超级管理员核对业务必要性；L3/L4 权限由另一名授权审批人批准。
3. 系统创建邀请，邀请链接一次性、短时有效；被邀请人完成身份验证并启用 MFA。
4. 授权人确认权限摘要，子账号激活；自动设置到期时间和定期复核日期。
5. 创建事件记录申请人、批准人、被授权人、范围、权限、时间和理由。

**预设权限模板：**

| 模板 | 允许 | 明确禁止 |
|---|---|---|
| 仅查看日志 | 读取获批范围日志、导出脱敏报表 | 写入/删除日志、看密钥、查看无关用户敏感数据 |
| 仅修改 DNS | 读取授权域名 DNS、修改允许的记录类型 | 域名转移/删除、批量跨租户修改、改 NS/DS（除非单独审批）、管理账号 |
| 仅查看订单 | 查看指定客户/工单订单状态 | 退款、改价、改账、导出全量个人信息 |
| 仅财务核验 | 查看付款凭证和对账字段 | DNS、用户权限、生产环境管理 |
| 只读运维 | 查看健康状态、指标、脱敏日志 | 发布、密钥读取、配置写入、用户数据修改 |

**子账号控制：**

- 权限按租户/域名/工单等资源范围限定；不得只授予宽泛的“管理员”标签。
- 默认有效期 30 天；续期须重新确认负责人和业务必要性。临时紧急授权最长 24 小时。
- 子账号不得创建更高权限子账号，不得修改自己的角色、MFA 政策或审计策略。
- 离职、岗位变化、合同终止或安全事件触发立即停用；访问令牌、会话和 API Key 同步撤销。
- 每月核对活跃子账号；连续 30 天未使用的非必要账号自动冻结并通知负责人。
- 导出数据应脱敏并按需审批；日志只读权限不得包含秘密、认证令牌或完整支付凭据。

**验收标准：** 子账号不能越权访问范围外资源；仅查看日志账号不能写日志；仅 DNS 账号不能修改 NS/DS 或转移域名（除非另行授权）；到期后访问立即拒绝；撤销后旧会话和令牌失效。

## 2. 审计与合规

### 2.1 必须审计的事件

至少覆盖以下事件类别：

- 身份与会话：登录成功/失败、登出、MFA 绑定/解绑/失败/恢复、密码重置、会话创建/撤销、异常设备/IP。
- 域名与领取：搜索/领取申请、领取成功/失败、注册、续费、赎回、转移、删除、状态变更。
- DNS：记录新增、修改、删除、批量操作、NS/DS/DNSSEC 变更、API 调用失败。
- 配额与计费：配额查看（敏感范围）、增加/减少、冻结、扣减、退款、对账差异和人工调整。
- 管理员操作：后台访问、用户查询、数据导出、封禁/解封、角色变更、子账号生命周期、策略配置。
- 安全与运维：密钥轮换、备份/恢复、发布/回滚、告警确认、熔断开启/关闭、审计管道异常。
- 拒绝与异常：权限拒绝、风控拒绝、速率限制、审批驳回、重复幂等请求和异常状态转换。

### 2.2 审计日志字段

每条事件至少包含：

| 字段 | 要求 |
|---|---|
| event_id | 全局唯一、不可复用 |
| event_type / action | 标准化事件类别和动作 |
| actor_id / actor_type | 操作人 ID 与用户/管理员/服务账号类型 |
| effective_role | 操作发生时的有效角色与权限版本 |
| occurred_at | UTC 时间戳，时钟同步；保留原始精度 |
| source_ip | 来源 IP；经过代理时记录可信代理链解析结果 |
| user_agent / device_id | 在合法且必要范围内记录 |
| target_type / target_id | 被操作资源及租户范围 |
| before / after | 变更前后值或经过脱敏的差异摘要 |
| result | 成功、失败、拒绝、部分成功 |
| reason / ticket_id | 操作理由、工单或审批编号 |
| request_id / correlation_id | 跨服务链路关联 ID |
| approver_id | 审批人及审批时间（如适用） |
| integrity | 前序哈希、当前哈希、签名/归档批次信息 |

禁止记录密码、完整访问令牌、私钥、恢复码、完整支付卡数据等秘密。对个人信息采用最小化和字段级脱敏。日志中需要保存敏感对象标识时，优先保存内部 ID，不复制不必要的原始内容。

### 2.3 防篡改机制：哈希链 + 外部归档

建议采用双层机制，不把单一数据库表视为不可篡改证据：

1. **追加写入：** 应用审计账号只允许 INSERT，不允许 UPDATE/DELETE；管理后台不提供日志编辑入口。
2. **规范序列化：** 事件按固定字段顺序和编码规范序列化，统一 UTC 时间、空值规则和字符编码。
3. **哈希链：** 每条记录计算 H_n = SHA-256(H_(n-1) || canonical_event_n)；链头定期签名。并发写入必须通过分区序号/单写入器或等价机制确保顺序一致。
4. **外部归档：** 按时间或批次将日志与链头写入独立账户/独立权限域的对象存储，启用对象锁定/WORM、版本控制和保留策略；归档密钥与业务密钥分离。
5. **独立校验：** 每日自动重算哈希链并核对归档清单；校验失败立即触发 P1 安全告警，冻结高风险写操作并保全现场。
6. **访问隔离：** 应用、运维和审计读取角色分离；生产管理员不得同时控制在线日志和外部归档删除权限。
7. **备份：** 审计数据和链头纳入备份；恢复演练需验证完整性，而非只验证文件可读。

**保留期限：** 默认建议在线可检索不少于 180 天、归档不少于 3 年；最终期限必须由法务/隐私负责人结合运营司法辖区、合同、行业要求和数据最小化原则批准。出现争议、调查或法律保全通知时执行 legal hold，暂停相关证据自动删除。

**验收标准：** 修改/删除历史日志会被权限拒绝或完整性校验发现；归档账户独立于生产账号；随机抽样可从事件重算到签名链头；恢复演练可验证哈希一致；审计故障有告警且高风险操作安全失败。

### 2.4 权限定期审计与报告

| 频率 | 审核对象 | 责任人 |
|---|---|---|
| 每月 | 管理员、子账号、服务账号、过期权限、异常登录 | 安全负责人主责，系统负责人协作 |
| 每季度 | 全部角色矩阵、权限模板、特权账号、职责分离 | 平台负责人组织，部门负责人确认 |
| 每半年 | 紧急账号、外部供应商、第三方集成、密钥访问范围 | 安全负责人 + 运维负责人 |
| 离职/转岗当日 | 账号、会话、密钥、VPN/云平台权限 | 人力/直属负责人发起，运维执行 |

**执行步骤：**

1. 导出当前账号、角色、资源范围、最近登录、最近使用时间、授权人和到期时间。
2. 与 HR/合同人员清单及服务账号登记表核对。
3. 标记孤儿账号、共享账号、长期未用账号、超范围权限、职责冲突和无负责人账号。
4. 业务负责人逐项确认“保留/缩权/冻结/删除”；高权限保留必须写明理由。
5. 运维在批准时限内执行；安全负责人复核变更结果及撤销令牌。
6. 出具审计报告，列明范围、日期、审计人、发现、风险等级、整改责任人、截止日期、证据链接和复测结果。
7. 未整改高危项升级平台负责人；逾期未关闭不得仅以口头承诺结案。

**报告验收：** 账号总数与身份源对账；所有特权账号均有负责人和 MFA 状态；发现项 100% 有责任人与期限；高危项关闭前有复测证据；报告归档且审计日志可追溯。

## 3. 核心业务流程与风控

### 3.1 域名生命周期管理

**前置原则：** 域名状态以注册局/注册商权威返回和本平台订单状态共同核验。缓存或演示数据不得作为注册、可用、续费成功或删除完成的依据。所有状态转换采用幂等请求、唯一业务流水号和可重试任务。

#### 3.1.1 状态机

待查询 → 可注册/不可注册 → 待确认 → 注册处理中 → 已注册/失败待补偿 → 正常持有 → 续费待处理 → 已续费/续费失败 → 宽限期 → 赎回期（如注册局适用） → 待删除/已删除

另设：转移处理中、争议/锁定、暂停服务、人工核查。不得仅凭本地定时器直接将域名标记为“已删除”；必须以注册商/注册局确认结果为准。各 TLD 的宽限期、赎回期、删除周期、转移锁定和费用不同，必须读取对应注册商/TLD 规则，不能统一假设固定天数。

#### 3.1.2 注册流程

**触发：** 用户提交注册订单并确认域名、后缀、价格、注册期限及条款。

1. 服务端重新查询域名可用性和价格；设置短时库存/价格有效窗口。
2. 校验用户身份、配额/支付状态、风险规则、制裁/滥用名单（如适用）及注册政策。
3. 展示完整费用、续费价格、限制、隐私保护选项和不可退款条件；用户明确确认。
4. 创建幂等订单；必要时先预授权/冻结额度，不重复扣款。
5. 对注册商 API 发起注册；记录供应商请求 ID、响应码和原始响应摘要。
6. 明确成功后更新域名状态、到期日和注册商标识；失败则按结果分类退款/释放预占。
7. 对超时但供应商结果未知的请求进入“结果待核实”，先查询供应商订单状态，不得盲目重复注册或重复扣款。
8. 通知用户并生成收据/操作记录。

**责任：** 用户发起；系统执行；运维负责供应商集成；财务核验资金；客服处理失败沟通；高风险异常由安全负责人介入。

**验收：** 重复请求不产生重复注册/扣款；超时状态可对账恢复；供应商确认、订单、资金流水一致；用户收到准确结果。

#### 3.1.3 续费流程

- 到期前 30/14/7/3/1 天发送通知（可配置，按 TLD 与用户偏好调整）。
- 自动续费仅在用户明确启用且支付授权有效时触发；续费前再次校验价格、付款方式、域名状态和注册商规则。
- 到期前 7 天执行第一次自动续费尝试；失败后按策略重试（例如 24 小时、72 小时），避免无上限扣款。
- 每次扣款均使用幂等键；失败通知用户并提供人工续费路径。
- 续费成功以注册商确认的新到期日为准；更新平台记录并发送凭证。
- 临近到期仍失败时提升提醒级别；客服不得承诺超出注册局政策的宽限时间。

**验收：** 提醒准确；自动续费有授权证据；失败重试有上限；订单、支付流水和注册商到期日一致。

#### 3.1.4 赎回流程

- 域名进入赎回期（若该 TLD/注册商存在）时，系统立即标记高风险状态并通知用户赎回截止时间、费用和可能无法恢复的风险。
- 用户提交赎回申请后，客服核验域名归属和申请人身份；财务核验费用；运维向注册商发起赎回。
- 赎回费用必须在操作前明确展示并经用户确认；不可保证注册商一定接受。
- 只有供应商确认恢复且状态/到期日更新后才标记成功。
- 若已超出赎回窗口或注册商拒绝，转人工解释并保留供应商证据。

**验收：** 每个赎回申请有截止时间、费用确认、供应商请求及最终结果；禁止未经确认收费。

#### 3.1.5 过期、删除与释放

- 到期后按注册商规则进入宽限/赎回/待删除状态；系统每日同步供应商状态。
- 用户未续费时发送到期及潜在删除通知；通知时间和渠道必须可审计。
- 删除前 72 小时（若规则允许）生成待删除任务，检查是否存在争议、转移、法律保全、欠费、锁定或未结工单。
- 删除/放弃域名属于不可逆或高影响操作，必须双人审批；用户明确申请的也需二次确认。
- 执行后等待注册商最终确认；只有确认释放后才更新为已删除/可重新注册。
- 删除失败或状态不明时进入人工核查，不得反复提交删除请求。

**验收：** 有完整通知、审批、供应商回执和状态同步；争议/法律保全域名不会自动删除；删除状态不由本地猜测生成。

### 3.2 DNS 变更操作流程

1. 请求人选择域名、记录类型、主机名、TTL、记录值和变更原因。
2. 服务端核验域名所有权、子账号范围、记录类型白名单、格式、冲突和风险。
3. 单条普通记录可按用户授权执行；NS、DS、DNSSEC、MX、CAA、批量记录或影响全站的变更列为 L3。
4. L3 变更须双人审批，审批摘要必须包含旧值、新值、TTL、影响范围、计划时间和回滚值。
5. 执行前保存配置快照；调用 DNS 服务商 API；记录供应商请求 ID 和结果。
6. 通过权威 DNS 查询和多个公共解析视角验证；按 TTL 观察传播情况。
7. 验证失败时停止后续批量任务，按回滚预案恢复旧值；无法恢复则升级 P1。
8. 通知请求人和受影响用户，工单闭环。

**防误操作：** 默认禁止跨租户批量变更；危险记录变更需显式二次确认；对 NS/DS 变更设置冷静期或人工核验；批量任务分批执行并设置最大影响域名数。

**验收：** 变更前后值、审批、供应商回执和解析验证可关联；失败自动停止；回滚后解析结果符合预期。

### 3.3 滥用处理 SOP

#### 3.3.1 投诉入口与分类

提供可访问的滥用投诉入口（例如 abuse@ 自有域名邮箱、网页表单和安全紧急联系方式）。入口需收集：投诉人联系方式、涉及域名/URL/IP、事件类型、发生时间及 UTC 时区、证据材料、紧急程度和善意声明。仅收集处理所需信息并提供隐私说明。

分类至少包括：钓鱼/恶意软件、垃圾邮件、欺诈、侵权投诉、僵尸网络/C2、未经授权访问、DNS 滥用、个人信息泄露、儿童安全紧急事件、执法/法院通知及其他违反服务条款行为。投诉不等同于事实成立；必须保留核验和申诉路径。

#### 3.3.2 处置阈值

| 级别 | 判定示例 | 初始动作 | 目标响应 |
|---|---|---|---|
| 紧急 / P0 | 正在发生的严重人身安全威胁、儿童性剥削材料、重大基础设施攻击、可信执法紧急请求 | 立即升级值班负责人和法务；在授权范围内采取最小必要临时限制；保全证据 | 15 分钟内确认受理，立即持续处置 |
| 高 / P1 | 已验证钓鱼、恶意软件分发、账户大规模失陷、关键 DNS 被劫持 | 立即限制明确涉事资源、吊销受影响凭据、通知安全负责人 | 30 分钟内确认，1 小时内形成处置计划 |
| 中 / P2 | 可信垃圾邮件、重复违规、可疑但证据不完整 | 风险评分、人工核验、限速/挑战/临时限制 | 4 小时内确认，1 个工作日内初步结论 |
| 低 / P3 | 一般政策咨询、证据不足的普通投诉 | 建单、补充材料、按队列调查 | 1 个工作日内确认 |

以上是内部服务目标，不构成对外法律承诺；值班团队必须按实际人力和合同公布可兑现的 SLA。任何自动处置阈值须经误报评估和法务/安全批准。

#### 3.3.3 自动与人工处置边界

- 自动系统可执行：速率限制、验证码/挑战、阻断明显恶意请求、临时冻结可疑 API Key、阻止已确认恶意 IOC 的请求。
- 自动系统不得仅凭单一低置信度信号永久封号、永久删除域名或公开披露用户身份。
- 高置信度且正在造成损害的行为，可先实施范围最小、可撤销的临时限制；同步通知值班人员并设置复核时限。
- 人工调查至少核对两类独立证据（如服务日志、供应商通知、样本/URL、用户反馈）；对争议投诉保留反证和申诉材料。
- 永久停用、域名删除、跨租户封禁、用户资金处理必须按权限矩阵审批。

#### 3.3.4 7×24 值班与升级

- 建立主值班/备值班/安全负责人/平台负责人/法务联系人轮值表；联系方式和替补每月验证。
- 值班人员收到告警后确认事件编号、时间线、影响范围和初步级别；未响应时自动升级至备值班，再升级平台负责人。
- P0/P1 建立专用事件频道；每 30 分钟更新一次状态，直到风险受控；P2 按小时更新。
- 采取措施遵循“保全证据 → 控制扩散 → 恢复服务 → 根因分析”的顺序；除紧急止损外不得先删除证据。
- 事件结束 5 个工作日内完成复盘，列出时间线、影响、根因、检测缺口、处置是否合规、补救措施、负责人和期限。

#### 3.3.5 配合执法与法律请求

1. 所有执法、监管、法院或律师请求统一进入法务/指定合规联系人，不由客服或运维自行判断法律效力。
2. 核验请求机构、签发权限、管辖范围、文书真实性、具体账户/域名、时间范围、所求数据和回复期限。
3. 对紧急口头请求记录请求人身份、法律依据、紧急性和后续书面补件期限；无法核验时升级法务。
4. 采用最小披露原则，只提供有效法律文书明确要求且依法可提供的数据；超范围请求寻求澄清或依法提出异议。
5. 执行数据保全时记录保全范围、时间、操作人、哈希值和访问链；限制内部访问并设置 legal hold。
6. 由法务批准回复内容和传输方式；使用加密渠道，验证接收方身份；保留发送回执。
7. 除法律禁止或妨碍调查外，按政策通知受影响用户；记录未通知的法律依据和复核时间。
8. 不得销毁、篡改、伪造或选择性隐匿相关证据。

**验收：** 投诉入口可用；值班名单和升级测试通过；每件投诉有编号、分类、时间线、证据、决定依据、审批及闭环记录；执法请求有法务审核与披露清单。

### 3.4 高风险操作熔断与回滚

**熔断触发条件（初始建议值，正式阈值须按基线压测和业务风险校准）：**

- DNS 批量变更失败率 5 分钟内超过 5%，或同一任务出现 3 次连续供应商错误：暂停该批次。
- DNS 权威解析与预期不符，或关键域名解析失败率超过 2% 且持续 3 分钟：暂停相关写操作并触发 P1。
- 注册/续费供应商 API 错误率 5 分钟超过 10%，或订单与资金状态不一致超过 3 笔：关闭自动重试，进入对账队列。
- 5 分钟内管理员失败登录超过 10 次/账号或出现异常 MFA 绕过迹象：冻结可疑会话并告警。
- 审计链校验失败、外部归档中断超过 15 分钟或审计写入失败：禁止 L3/L4 操作。
- 未经批准的角色提升、超级管理员 MFA 被关闭、审计策略被修改：立即 P1，冻结权限变更并保全证据。
- 用户配额短时异常增加超过审批阈值或跨租户写入：暂停配额写入并核对流水。

**熔断执行：**

1. 任何值班运维可按预定义条件启动临时熔断；记录触发指标、时间、影响范围和执行人。
2. 系统应暂停对应操作类型/供应商/租户范围，不应无差别关闭无关只读服务。
3. 通知安全负责人和平台负责人；L3/L4 熔断关闭必须由双人批准。
4. 确认故障恢复、队列积压、数据一致性和审计链完整后，按小流量/单资源灰度恢复。
5. 记录熔断持续时间、误报/漏报、影响和复盘任务。

**回滚原则：**

- DNS：回放经审批的变更前快照；确认记录值、TTL、NS/DS 和权威解析；注意 DNS 缓存传播，不能承诺即时全球生效。
- 配额：依据不可变更的流水执行补偿交易，不直接覆盖历史记录；核对用户余额/配额与账本。
- 域名订单：按供应商状态查询后执行补偿，不盲目重复注册/退款。
- 权限：恢复上一已批准策略版本，撤销新会话、令牌和 API Key；检查提权期间的访问记录。
- 发布：部署上一个已验证制品或切回稳定版本；数据库迁移必须采用向前兼容/补偿迁移，不得假设代码回滚即可恢复数据。
- 密钥泄露：吊销旧密钥、轮换新密钥、检查调用记录；不得把旧密钥重新启用作为回滚方案。

**验收：** 每类高风险操作有明确熔断开关、负责人、回滚数据源和验证步骤；季度至少一次演练；演练记录包含恢复时间、数据一致性结果和问题整改。

## 4. 上线与运维 SOP

### 4.1 上线就绪检查清单（Go / No-Go）

发布负责人逐项记录“通过/不适用/未通过”，未通过的关键项不得上线。

#### 安全与权限

- [ ] 生产管理员全部启用 MFA；无共享管理员账号；紧急账号已登记并封存。
- [ ] RBAC 在服务端实施；关键 API 已完成越权、跨租户和 IDOR 测试。
- [ ] 子账号权限模板、资源范围、到期和撤销机制通过测试。
- [ ] 密钥存储在受控密钥管理服务；无密钥、Token、密码进入代码仓库、构建日志或前端包。
- [ ] 依赖漏洞、静态分析、秘密扫描和基础安全测试完成；高危漏洞为零或有书面风险接受。
- [ ] 登录限流、会话撤销、CSRF/CORS、输入校验和安全响应头已验证。
- [ ] 审计覆盖关键事件；防篡改归档与告警通过演练。
- [ ] 管理后台访问策略、数据脱敏和导出审批已启用。

#### 功能与业务

- [ ] 域名注册/续费/赎回/删除状态与供应商规则一致；未启用的能力明确禁用。
- [ ] DNS 变更具备所有权校验、快照、审批、解析验证和回滚。
- [ ] 幂等、重试、超时未知结果处理和对账流程通过测试。
- [ ] 滥用投诉入口、值班联系人、升级流程和申诉机制可用。
- [ ] 用户通知、价格、续费条件、退款规则和服务条款经业务/法务审核。
- [ ] 演示数据明确标注，不会误导为真实库存或真实注册状态。

#### 性能与可靠性

- [ ] 完成容量评估与压测；记录峰值并发、P95/P99 延迟、错误率和资源利用率。
- [ ] 关键 API 有超时、限流、熔断、退避重试和队列积压保护。
- [ ] 数据库连接池、索引、慢查询和容量告警已验证。
- [ ] 依赖供应商降级时，用户界面准确显示处理中/失败，不伪报成功。
- [ ] 健康检查、合成监控和外部可用性探测通过。

#### 备份与恢复

- [ ] 数据库自动备份已启用并加密；备份账号与生产写账号隔离。
- [ ] 备份保留策略、跨区域/独立账户副本和访问权限已确认。
- [ ] 最近一次恢复演练成功；验证数据一致性、权限、审计链和文件对象。
- [ ] RPO/RTO 已由业务负责人批准并有测量证据。
- [ ] 关键配置、DNS 变更快照、密钥恢复程序（不含明文密钥）和供应商联系人已归档。

#### 发布治理

- [ ] 变更单、影响评估、测试报告、发布窗口、值班人员和回滚负责人明确。
- [ ] 代码审查至少一名非作者批准；涉及安全/权限/资金/DNS 的变更由对应负责人复核。
- [ ] 构建制品可追溯到提交 SHA、依赖锁文件和构建记录。
- [ ] 数据库迁移向前兼容，回滚/补偿脚本已在预发布验证。
- [ ] 发布后验证脚本、监控面板和告警接收人准备完成。

**Go/No-Go 决策：** 发布负责人汇总；运维、安全、业务负责人对各自领域签字。任何 P0/P1 未关闭、审计不可用、管理员 MFA 未强制、备份无法恢复或回滚方案未验证，均为 No-Go。

### 4.2 标准发布手册

**角色：** 变更申请人、发布负责人、执行运维、代码审查人、安全复核人、业务验收人。

1. **提出变更：** 创建变更单，说明目的、范围、提交 SHA、风险等级、依赖、数据迁移、影响用户、计划窗口和回滚方案。
2. **评审：** 代码审查；安全/隐私/财务/DNS 相关负责人按影响参加评审。L3/L4 必须双人批准。
3. **预发布：** 使用接近生产的配置和脱敏数据；执行构建、单元/集成/E2E、安全、性能和迁移测试。
4. **备份与冻结：** 发布前确认备份成功；记录当前稳定版本、配置快照和数据库迁移版本；必要时进入变更冻结。
5. **发布：** 优先采用灰度/金丝雀（例如 5% → 25% → 50% → 100%）；每阶段观察至少一个关键业务窗口或足够样本量。无法灰度的变更须说明原因并加强验证。
6. **验证：** 检查健康检查、登录/MFA、核心 API、域名查询、DNS 只读/写入（仅测试域名）、审计落库、队列、错误率和延迟。
7. **扩大流量：** 只有当前阶段指标正常、业务验收通过才进入下一阶段。
8. **结束：** 记录制品版本、提交 SHA、开始/结束时间、执行人、审批人、验证证据和遗留风险；通知相关人员。
9. **观察期：** 发布后至少 30 分钟重点观察；高风险变更按风险延长至 24 小时。

**禁止事项：** 直接在生产手工改代码；绕过审查推送；在没有备份/回滚的情况下做破坏性迁移；使用真实客户数据做非必要测试；未经审批修改 DNS、权限或财务数据。

### 4.3 回滚步骤

1. 触发回滚：核心功能不可用、关键错误率超阈值、数据一致性异常、安全控制失效或业务负责人判断风险不可接受。
2. 宣布回滚并冻结相关变更；指定一名事件指挥人，所有操作关联事件编号。
3. 确认回滚范围：应用制品、配置、数据库、DNS、权限或供应商集成；避免不必要的全站回滚。
4. 应用回滚：切回上一稳定制品/流量路由；确认健康检查和关键请求。
5. 数据处理：先判断迁移是否可逆；使用经验证的向前修复或补偿脚本；不得直接删除已产生的业务记录。
6. DNS/外部服务：按变更快照恢复；查询权威解析并持续监测缓存传播。
7. 安全验证：确认管理员 MFA、RBAC、审计写入和告警仍有效；若回滚涉及凭据，撤销并轮换。
8. 业务核对：对账订单、付款、配额、域名状态和供应商结果；处理未知状态队列。
9. 通知用户与内部团队，说明影响范围、当前状态和后续安排；不得披露不必要的安全细节。
10. 复盘：24 小时内完成初步报告，5 个工作日内完成根因与整改计划。

**回滚验收：** 服务恢复到约定 SLO；关键数据对账一致；没有重复扣款/重复注册；DNS 解析符合预期；审计链连续；回滚全过程可追溯。

### 4.4 核心监控指标与建议告警

以下为初始建议阈值，正式上线前须根据压测基线、业务量和供应商 SLA 校准。告警应按持续时间、错误预算和业务影响去重，避免告警风暴。

| 指标 | 建议告警阈值 | 级别 | 主要响应人 |
|---|---|---|---|
| 网站/API 可用性 | 5 分钟低于 99.5% | P1 | 运维 |
| 核心 API P95 延迟 | 连续 10 分钟高于 800ms | P2；影响交易升 P1 | 运维 |
| 核心 API 5xx | 5 分钟超过 2% | P1/P2 | 运维 |
| 登录失败率 | 5 分钟超过基线 3 倍 | P2；疑似攻击升 P1 | 安全 |
| MFA 异常/管理员登录 | 任意可疑绕过或异常管理员登录 | P1 | 安全 |
| RBAC 拒绝异常 | 单主体短时异常激增 | P2 | 安全 |
| 审计写入延迟 | 超过 60 秒 | P1 | 运维/安全 |
| 哈希链/归档完整性 | 任一校验失败 | P1 | 安全 |
| DNS 解析失败 | 关键域名多探针失败 3 分钟 | P1 | 运维 |
| DNS 变更失败率 | 5 分钟超过 5% | P1/P2 | 运维 |
| 注册/续费供应商错误率 | 5 分钟超过 10% | P1/P2 | 运维 |
| 订单/资金对账差异 | 任一无法解释的差异 | P1 | 财务/运维 |
| 配额异常变更 | 超审批额度或跨租户变化 | P1 | 安全/运维 |
| 队列积压 | 超过业务设定容量或持续增长 10 分钟 | P2 | 运维 |
| 数据库连接/存储 | 连接池 80% 或磁盘 80% | P2 | 运维 |
| 备份任务 | 任一关键备份失败或超时 | P1/P2 | 运维 |
| 证书到期 | 30/14/7 天提醒 | P2 | 运维 |

### 4.5 告警响应流程

1. 监控平台生成唯一告警编号，附指标、阈值、持续时间、受影响服务和关联部署。
2. 值班人员按级别确认：P0 5 分钟、P1 10 分钟、P2 30 分钟、P3 1 个工作日内（目标值）。
3. 初步判断是否安全事件、数据事件、供应商故障或发布回归；建立事件频道和时间线。
4. 控制影响：限流、熔断、隔离、回滚或切换只读；涉及数据时先保全证据。
5. 通知责任人和受影响团队；对用户可见故障按沟通政策更新状态页/公告。
6. 恢复后持续观察至少 30 分钟；确认错误率、延迟、队列和数据一致性恢复。
7. 关闭告警需填写根因、影响、操作、恢复时间、是否涉及个人数据/资金、后续行动。
8. P0/P1 必须复盘；整改项登记责任人和截止时间，并在关闭前复测。

**事件级别：**

- **P0：** 重大安全/数据泄露、核心服务全面中断、资金或域名大规模错误、法律紧急事件。立即启动应急指挥。
- **P1：** 核心流程严重受损、单区域/关键供应商故障、审计或权限控制失效。立即响应并考虑熔断。
- **P2：** 部分功能降级、非关键告警、可绕行故障。按值班流程处理。
- **P3：** 低影响问题、容量趋势、一般咨询。进入常规队列。

## 5. 职责分工（RACI）

R = 执行（Responsible）；A = 最终负责/批准（Accountable）；C = 会商（Consulted）；I = 知会（Informed）。

| 流程 | 平台负责人 | 安全负责人 | 运维 | 客服 | 财务 | 法务/合规 |
|---|---|---|---|---|---|---|
| RBAC 角色政策 | A | R | C | C | C | C |
| 管理员 MFA | A | R | R | I | I | C |
| 子账号审批 | A | R | C | I | I | I |
| 权限月审/季审 | A | R | R | C | C | C |
| 审计日志与归档 | A | R | R | I | I | C |
| 域名注册/续费 | A | C | R | R（沟通） | R（资金核验） | C |
| DNS 高风险变更 | A | C | R | I | I | I |
| 滥用投诉处置 | A | R | R | R | I | C/R（法律请求） |
| 资金/配额对账 | A | C | C | I | R | C |
| 生产发布/回滚 | A | C | R | I | I | I |
| 事件复盘 | A | R | R | C | C | C |

每个岗位必须有主责人与替补；实际组织中若无独立法务/安全岗位，须指定具备授权的外部顾问或负责人，不得省略审核职责。

## 6. 记录、报告与验收总表

| 控制项 | 必须留存的证据 | 验收标准 | 周期 |
|---|---|---|---|
| RBAC | 权限矩阵、授权记录、越权测试报告 | 默认拒绝；跨租户测试无越权 | 每季度及重大变更 |
| MFA | 管理员 MFA 状态、恢复与紧急访问记录 | 后台与管理 API 均强制 MFA | 持续监控/月审 |
| 子账号 | 申请、批准、权限范围、到期、撤销记录 | 权限不可越界；到期立即失效 | 每月 |
| 审计 | 事件样本、字段完整性、查询记录 | 关键事件覆盖率 100% | 每月抽检 |
| 防篡改 | 哈希校验、外部归档、恢复演练报告 | 篡改可检测；归档独立可验证 | 每日校验/季度演练 |
| 域名生命周期 | 状态机、供应商回执、通知、订单流水 | 状态与供应商一致；幂等无重复操作 | 每月抽检 |
| 滥用处理 | 投诉工单、分级、处置证据、复盘 | SLA 统计完整；证据和申诉可追溯 | 每月 |
| 熔断回滚 | 演练记录、回滚快照、验证结果 | 能在批准 RTO 内恢复 | 每季度 |
| 发布 | 变更单、审批、测试、制品 SHA、验收 | Go/No-Go 签字齐全 | 每次发布 |
| 备份恢复 | 备份报告、恢复测试、RPO/RTO 结果 | 恢复成功且数据一致 | 每月备份抽检/季度恢复演练 |
| 监控告警 | 面板、告警记录、响应时间、复盘 | P0/P1 有值班确认与闭环 | 持续/月报 |

### 6.1 月度运营报告

平台负责人每月组织生成运营与控制报告，至少包含：

- 服务可用性、核心 API P95/P99、错误率和容量趋势；
- 注册、续费、赎回、删除、DNS 变更的成功率和失败原因；
- 登录/MFA 异常、权限拒绝、特权账号和子账号变化；
- 审计日志完整性、归档状态和校验结果；
- 滥用投诉数量、分级、响应时长、误报/申诉和处置结果；
- 发布次数、回滚次数、变更失败率和未关闭风险；
- 备份成功率、恢复演练结果、RPO/RTO 达成情况；
- 未整改问题、风险接受记录、责任人和到期日。

报告由平台负责人签署；安全、运维、客服、财务对各自数据确认。重大风险不得隐藏在汇总数字中，必须单独列项。

## 7. 实施优先级与上线门槛

### P0：任何真实管理员或真实业务数据上线前

- 服务端 RBAC 和租户/资源级授权；
- 管理员强制 MFA 与会话撤销；
- 关键操作审计和审计失败安全策略；
- 密钥管理、备份、恢复演练；
- 生产环境监控、值班联系人和事件升级；
- DNS/域名写操作审批、幂等与回滚；
- 投诉入口和安全事件响应责任人。

### P1：开放域名注册、续费、配额或资金相关能力前

- 注册商状态同步、订单幂等、超时未知状态核验；
- 配额/资金不可变流水与财务对账；
- 子账号授权与到期撤销；
- 哈希链及独立 WORM 归档；
- 滥用处置 7×24 轮值及法律请求流程；
- 熔断和回滚演练。

### P2：规模化运营前

- 自动权限审计报告；
- 多区域备份与灾难恢复；
- 供应商 SLA 监控和故障切换；
- 定期渗透测试、桌面演练和独立控制审计；
- 指标阈值按实际 SLO/错误预算校准。

**最终上线准入：** P0 控制未完成，不得开放真实高权限后台或真实域名/DNS 写操作；P1 控制未完成，不得开放相应资金、配额或域名生命周期自动化功能。所有例外必须由平台负责人和安全负责人书面批准，注明范围、补偿控制、到期日和风险接受人。
